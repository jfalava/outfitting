Native package `update` upgrades software that is already installed. It does not install missing declared packages or prune anything; use [`apply`](/docs/cli/apply/) for package presence. Nix actions build or activate declarative configurations, so activation can add, replace, or remove managed packages.

```bash
outfitting-manager update <subcommand> [flags]
```

The bare command prints the subcommands available on the current platform. Successful updates publish their related lock or inventory state by default; `--no-push` keeps that write local and skips its upload.

Update global Bun packages directly:

```bash
bun update -g
```

## macOS

### `update brew`

Upgrade installed Homebrew packages and record the observed inventory. It does not install missing Brewfile entries.

```bash
outfitting-manager update brew
outfitting-manager update brew --no-push
```

### `update nix` (macOS)

Choose `build`, `test`, `dry`, or `switch`. Bare `update nix` lists these actions without running one.

```bash
outfitting-manager update nix build
outfitting-manager update nix switch
outfitting-manager update nix switch --no-push
outfitting-manager update nix switch --no-refresh
```

Nix actions publish the `nix` lock after a successful build or activation. On macOS, an unavailable remote lock falls back to the local lock or a lock generated by Nix, so a machine can bootstrap without a lock already stored in the Worker.
Managed sparse Nix sources refresh by default; `--no-refresh` uses the existing local source. Explicit `OUTFITTING_REPO` checkouts remain local. This does not make package downloads offline.

### `update all`

Run `nix switch`, then update Homebrew. It continues after a failed step and exits nonzero if any step failed.

```bash
outfitting-manager update all
outfitting-manager update all --no-push
outfitting-manager update all --no-refresh
```

## Windows

Choose `winget`, `scoop`, or `all`. WinGet and Scoop upgrade installed packages only; missing declarations belong to `apply`. `all` runs both managers and records successful steps even if another step fails.

```powershell
outfitting-manager update winget
outfitting-manager update scoop --no-push
outfitting-manager update all
```

## Linux

Choose `all`, `apt`, or `pacman`. `all` uses the saved Linux profile: `generic-linux` upgrades native packages only, while `oci-agents` and `ubuntu-wsl` refresh and switch Home Manager before upgrading native packages. The native forms remain independent and never run Nix. `all` detects the package manager, with an optional `--package-manager apt|pacman` override. Passing `--offline` refuses the aggregate operation rather than silently skipping one of its steps.

```bash
outfitting-manager update all
outfitting-manager update all --no-refresh
outfitting-manager update apt
outfitting-manager update pacman
```

Nix-backed profiles also support `update nix build|test|dry|switch`, using the saved Linux profile. These actions refresh the active profile's complete local source closure before evaluating the flake unless `--no-refresh` is passed. Refresh never runs `nix flake update`; checked-in `flake.lock` changes must come from the configured source.
Successful Linux Nix actions publish the profile's related `nix` lock; add `--no-push` to skip that upload. Native `apt` and `pacman` updates have no related remote lockfile.

## Platform differences

| Platform | `update` subcommands          | Main difference                                                                                            |
| -------- | ----------------------------- | ---------------------------------------------------------------------------------------------------------- |
| macOS    | `brew`, `nix`, `all`          | `nix` manages nix-darwin and `brew` upgrades installed Homebrew packages.                                  |
| Windows  | `winget`, `scoop`, `all`      | Upgrades installed packages only; state is uploaded unless `--no-push` is set.                             |
| Linux    | `all`, `apt`, `pacman`, `nix` | `all` updates Home Manager for Nix-backed profiles, then native packages; targeted forms stay independent. |
