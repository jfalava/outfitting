`update` upgrades software already installed through one native package manager. It does not install missing declared packages or prune anything; use [`apply`](/docs/cli/apply/) for package presence. Nix has its own top-level command, [`nix`](/docs/cli/nix/), and manager-binary replacement is [`self-update`](/docs/cli/self-update/).

```bash
outfitting-manager update [--package-manager <manager>] [flags]
```

There is no aggregate `update all`: run each operation you intend explicitly. Successful Windows package operations and the macOS Homebrew inventory are published by default; `--no-push` keeps the related state local.

Update global Bun packages directly:

```bash
bun update -g
```

## macOS

### macOS: Homebrew

Upgrade installed Homebrew packages and record the observed inventory. It does not install missing Brewfile entries.

```bash
outfitting-manager update
outfitting-manager update --no-push
```

On macOS, `update` upgrades Homebrew packages only. It does not install missing Brewfile entries; use [`apply`](/docs/cli/apply/) for that.

### Linux: apt or pacman

```bash
outfitting-manager update
outfitting-manager update --package-manager apt
outfitting-manager update --package-manager pacman
outfitting-manager update --package-manager apt --offline
```

Linux detects the native package manager by default. `--package-manager apt|pacman` selects one explicitly. `--offline` refuses the update because a network-free system upgrade cannot be guaranteed.

### Windows: WinGet or Scoop

Windows requires an explicit package manager. Each invocation upgrades through exactly one of WinGet or Scoop.

```powershell
outfitting-manager update --package-manager winget
outfitting-manager update --package-manager scoop --no-push
```

Missing declarations belong to [`apply`](/docs/cli/apply/). To upgrade both Windows managers, run two separate commands. Each successful operation records its own state; `--no-push` skips publishing it.
