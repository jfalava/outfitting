Native package `update` upgrades software that is already installed. It does not install missing declared packages or prune anything; use [`apply`](/docs/cli/apply/) for package presence. Nix actions build or activate declarative configurations, so activation can add, replace, or remove managed packages.

```bash
outfitting-manager update <subcommand> [flags]
```

The bare command prints the subcommands available on the current platform. When an update records local state, `--no-push` keeps that write local and skips its upload.

Update global Bun packages directly:

```bash
bun update -g
```

## macOS

### `update brew`

Upgrade installed Homebrew packages and record the observed inventory. It does not install missing Brewfile entries.

```bash
outfitting-manager update brew
outfitting-manager update brew --no-push
```

### `update nix`

Choose `build`, `test`, `dry`, or `switch`. Bare `update nix` lists these actions without running one.

```bash
outfitting-manager update nix build
outfitting-manager update nix switch
```

### `update all`

Run `nix switch`, then update Homebrew. It continues after a failed step and exits nonzero if any step failed.

```bash
outfitting-manager update all
outfitting-manager update all --no-push
```

## Windows

Choose `winget`, `scoop`, or `all`. WinGet and Scoop upgrade installed packages only; missing declarations belong to `apply`. `all` runs both managers and records successful steps even if another step fails.

```powershell
outfitting-manager update winget
outfitting-manager update scoop --no-push
outfitting-manager update all
```

## Linux

Choose `all`, `apt`, or `pacman` to upgrade installed native packages. These forms do not select a profile or install missing declarations. `all` detects the package manager, with an optional `--package-manager apt|pacman` override. Passing `--offline` refuses upgrades rather than silently using the network.

```bash
outfitting-manager update all
outfitting-manager update apt
outfitting-manager update pacman
```

Nix-backed profiles also support `update nix build|test|dry|switch`, using the saved Linux profile.

## Platform differences

| Platform | `update` subcommands          | Main difference                                                                              |
| -------- | ----------------------------- | -------------------------------------------------------------------------------------------- |
| macOS    | `brew`, `nix`, `all`          | `nix` manages nix-darwin and `brew` upgrades installed Homebrew packages.                    |
| Windows  | `winget`, `scoop`, `all`      | Upgrades installed packages only; state is uploaded unless `--no-push` is set.               |
| Linux    | `all`, `apt`, `pacman`, `nix` | Native forms upgrade installed packages; `nix` operates Home Manager on Nix-backed profiles. |
