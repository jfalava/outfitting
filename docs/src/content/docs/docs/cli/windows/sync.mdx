`sync` fetches the selected profile files from the configured raw source, reconciles WinGet and Scoop, materializes the configured PowerShell profile, and writes `windows.lock.json`.

```powershell
outfitting-manager sync
outfitting-manager sync --profile base,dev
outfitting-manager sync --profile base --winget-only
outfitting-manager sync --no-push
```

Options are `--profile`, `--winget-only`, and `--no-push`. Regular profiles are canonical. They include Microsoft Store entries marked as `msstore:<id>` in the manifest, and the CLI installs those entries with `--source msstore`.

When reusing a saved selection, a mixed legacy selection such as `base,msstore-base` migrates to `base`. A standalone `msstore-base` selection errors because selecting `base` would also install non-Store packages; rerun with an explicit regular selection such as `outfitting-manager sync --profile base`. `--no-push` keeps the lock local. Untracked native WinGet and Scoop installs remain unmanaged.

Each sync lists tracked packages outside the selected baseline and asks before removing them. Declining aborts before package operations or lock writes.
