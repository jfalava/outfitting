`lockfiles` stores generated state that is not committed to Git, such as the canonical macOS flake lock and the Windows unified package lock. On Windows, `sync` is the desired-state reconciliation command; use `lockfiles` for direct remote lock transport.

- Push state to the API worker behind the edge router.
- Restore, list, and inspect stored state on another machine.
- Update the executable with [Upgrade](/docs/cli/upgrade).

It accepts any machine and kind. Files tracked by Git are refused because commits already preserve them.

Public API URL (via the edge router): `https://worker-url/api`.

## Configure lockfile storage

Point the CLI at your deployed Worker. See [Provision credentials](/docs/cli/provision#credentials) for where configuration is stored.

```bash
outfit lockfiles configure-worker "https://url-to-your-worker"
```

If it has not been configured, the first API call prompts for it and for the bearer token using masked input. Run `configure-worker` again whenever the Worker URL changes, and `configure-token` to set or replace the API token:

```bash
outfit lockfiles configure-token
```

## Push lock state

```bash
outfit lockfiles push machine-name:aarch64-darwin nix updated-flake.lock
outfit lockfiles push machine-name:aarch64-darwin homebrew-inventory homebrew-inventory.txt
outfit lockfiles push machine-name:x86_64-windows windows "$HOME/.config/outfitting/windows.lock.json"
```

Protect a read-modify-write update by supplying the SHA-256 of the version that was pulled:

```bash
outfit lockfiles push machine-name:aarch64-darwin nix updated-flake.lock \
  --if-match 0123456789abcdef0123456789abcdef0123456789abcdef0123456789abcdef
```

The Worker rejects the push with HTTP 412 if another client has advanced that machine and kind. Retrying content that is already current succeeds.

## Pull and inspect lock state

Pull the latest version:

```bash
outfit lockfiles pull machine-name:x64-wsl nix
outfit lockfiles pull machine-name:x86_64-windows windows restored-windows.lock.json
```

The default output filename is inferred for common kinds, including `nix`, `flake`, `bun`, `npm`, `package-lock`, `homebrew-inventory`, `homebrew`, `brew`, `brewfile`, `powershell-inventory`, `private-fonts`, and `windows`. Pass an explicit output path for any other free-form kind.

List kinds and inspect history:

```bash
outfit lockfiles list machine-name:aarch64-darwin
outfit lockfiles history machine-name:aarch64-darwin nix
```

Machine names are free-form. The manager's automatic Windows id uses the `username:x86_64-windows` convention; pass `setup --machine-id` to override it.

## Worker API

Every request requires `Authorization: Bearer OUTFITTING_LOCKFILES_TOKEN`.

Paths below are relative to the API worker. Through the router they are prefixed with `/api` (the router strips that prefix before forwarding).

| Method   | Route                               | Result                                                |
| -------- | ----------------------------------- | ----------------------------------------------------- |
| `PUT`    | `/lockfiles/:machine/:kind`         | Stores/promotes the body and returns `{ hash, size }` |
| `GET`    | `/lockfiles/:machine/:kind`         | Returns the latest raw content as text                |
| `GET`    | `/lockfiles/:machine/:kind/history` | Returns `{ hash, size, created_at }[]`, newest first  |
| `GET`    | `/lockfiles/:machine`               | Returns a sorted JSON array of tracked kinds          |
| `DELETE` | `/lockfiles/:machine/:kind/:hash`   | Deletes one D1 row                                    |

Public equivalents: `https://worker-url/api/lockfiles/...`.

`PUT` accepts an optional standard `If-Match: "sha256"` header. The D1 promotion and head update are atomic; a stale expected hash returns HTTP 412 without advancing the head. Deleting the current head returns HTTP 409.

## Platform integrations

- macOS uses the `nix` kind as its canonical remote flake lock. Nix update commands pull it into a temporary path and build with `--reference-lock-file` and `--no-write-lock-file`. A failed pull aborts the update. Normal updates do not upgrade flake inputs, publish a new lock, or create a recovery checkpoint; `outfit recover nix` only resumes an existing checkpoint.

* Successful `outfit update brew` and `outfit snapshot brew` operations automatically store the observed, versioned Homebrew state as `homebrew-inventory`. Kinds are free-form and require no schema migration.

* Windows uses `windows.lock.json` as its unified machine lock. `outfit sync` pulls selected WinGet and Scoop manifests from GitHub, reconciles the baseline, records manual `outfit winget|scoop install/uninstall` operations, and uploads the lock as kind `windows`. The old `winget`, `scoop-inventory`, and `bun-global-inventory` kinds remain readable for migration but are no longer written by the normal Windows update path.
