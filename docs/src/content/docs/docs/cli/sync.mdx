`sync` is deliberately platform-specific. It reconciles package presence on Windows and Linux; on macOS it is the primary command for remote lockfile transport.

## Invoke `sync`

```bash
outfitting-manager sync [subcommand] [flags]
```

The machine id is inferred from `OUTFITTING_MACHINE_ID`, `config.json`, or the automatic `user:arch-os` value. It is not a positional argument.

## Shared lockfile subcommands

These subcommands are available below `sync` on every platform. [`lockfiles`](/docs/cli/lockfiles/) is an alias for the same remote operations.

### `sync configure-worker`

Store the lockfiles Worker URL.

```bash
outfitting-manager sync configure-worker https://example.com/api
```

### `sync configure-token`

Prompt for and store the Worker API token.

### `sync push`

Upload a local lockfile. Omit the kind, or pass `all`, to push every known local lock path.

```bash
outfitting-manager sync push nix updated-flake.lock
outfitting-manager sync push
```

Use `--if-match <sha256>` for an optimistic-concurrency check.

### `sync pull`

Download one lockfile or all tracked kinds. Known kinds get a default output path; pass an explicit path when needed.

```bash
outfitting-manager sync pull nix
outfitting-manager sync pull windows restored-windows.lock.json
outfitting-manager sync pull
```

### `sync list`

List lockfile kinds tracked for the inferred machine.

### `sync history`

Show version history for one kind or, when omitted, every tracked kind.

```bash
outfitting-manager sync history nix
outfitting-manager sync history
```

## Linux package subcommands

### `sync all`

Install missing declared packages using detected apt or pacman. Unrelated installed packages are preserved.

### `sync apt`

Install missing declared apt packages without removing unrelated packages.

### `sync pacman`

Install missing declared pacman packages without removing unrelated packages.

The Linux package forms accept `--profile` and `--offline`.

## Windows package synchronization

### Bare `sync`

On Windows, bare `sync` fetches the selected WinGet and Scoop manifests, installs the desired packages, removes tracked packages outside the selected baseline after confirmation, refreshes the PowerShell profile, and writes `windows.lock.json`.

```powershell
outfitting-manager sync
outfitting-manager sync --profile base,dev
outfitting-manager sync --profile base --winget-only
outfitting-manager sync --no-push
```

`--winget-only` skips Scoop while bootstrapping. `--no-push` writes the local lock without uploading it. Regular profiles include Microsoft Store entries marked `msstore:<id>`.

## Platform differences

| Platform | Meaning of `sync` | Invocation |
| --- | --- | --- |
| macOS | Remote inventory and lockfile transport. There is no package-reconciliation action named bare `sync`. | `outfitting-manager sync push nix updated-flake.lock`; use `sync configure-worker|configure-token|pull|list|history` for the other operations. |
| Windows | Desired-state package reconciliation for WinGet and Scoop, including the unified `windows.lock.json`. | `outfitting-manager sync [--profile base,dev]`; use `outfitting-manager lockfiles <subcommand>` for direct remote lockfile transport. |
| Linux | Presence-based package reconciliation for apt or pacman. Missing declared packages are installed; unrelated packages are not removed. | `outfitting-manager sync all|apt|pacman`; use `outfitting-manager sync [lockfile-subcommand]` for remote transport. |
