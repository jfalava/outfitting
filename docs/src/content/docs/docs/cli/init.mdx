`init` prepares the state root and validates the selected BYOR source. It does not install, upgrade, remove, or activate anything. The source must be either a local checkout with root `outfitting.json` or a remote Git source configured in the state-root `byor.json` map.

## Usage

```bash
outfitting-manager init --repo ~/src/machine-config --profile workstation
outfitting-manager init --profile workstation
outfitting-manager init --profile workstation --no-refresh
```

Use `--repo <path>` or `OUTFITTING_REPO` for a local checkout. Otherwise, configure a remote with [`outfitting-manager byor`](/docs/cli/byor/). `--profile` selects a declaration from `outfitting.json` or `byor.json`; Linux requires an explicit profile during initialization.

`--no-refresh` validates and reuses the existing remote snapshot instead of fetching. It cannot create a missing snapshot. Local checkouts are always read directly and are never fetched from their Git remote.

Use [`validate`](/docs/cli/validate/) to check a local contract before selecting it. See [Source configuration](/docs/source-configuration/) for precedence, migration, and offline behavior.

## Platform differences

| Platform | What `init` prepares                                                                |
| -------- | ----------------------------------------------------------------------------------- |
| macOS    | The selected macOS BYOR profile and its declared Nix, Brewfile, and optional paths. |
| Windows  | The selected composable WinGet profiles and any declared shared Windows components. |
| Linux    | The explicitly selected Linux profile and its apt, pacman, and/or Nix declarations. |
