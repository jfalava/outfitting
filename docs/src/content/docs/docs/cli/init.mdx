`init` creates the local state root, saves configuration, and fetches the declarations needed by later commands. It does not install, upgrade, remove, or activate anything.

## Usage

```bash
outfitting-manager init
outfitting-manager init --no-fetch
```

Common source options are [`--machine-id`](/docs/cli/profiles/#machine-id), `--manifest-base-url`, `--manifest-ref`, and `--no-fetch`. macOS and Linux also accept `--repo`; Windows and Linux accept `--profile` as described in [Profiles](/docs/cli/profiles/).

`--no-fetch` creates or refreshes configuration while using declarations already cached in the state root. Source overrides are saved for later commands.

## Platform differences

| Platform | What `init` prepares                                                                                 | Platform-specific invocation                                            |
| -------- | ---------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| macOS    | A sparse macOS source or a saved local checkout, validated for the nix-darwin and Brewfile contract. | `outfitting-manager init --repo ~/src/my-machine-config`                |
| Windows  | Configured manifests and the cached PowerShell profile.                                              | `outfitting-manager init --profile base,dev`                            |
| Linux    | The selected profile-scoped source and persisted `linux.profile`.                                    | `outfitting-manager init --profile ubuntu-wsl --repo ~/code/outfitting` |
