`update` owns the macOS package and system update paths. Run one manager or the aggregate workflow:

```bash
outfit update nix
outfit update brew
outfit update all
```

## Nix-darwin

Bare `update nix` only lists subcommands. The actions are:

```bash
outfit update nix         # lists build | switch | test | dry
outfit update nix build   # Build without activating
outfit update nix test    # Test-build without activating
outfit update nix dry     # Dry-run without activating
outfit update nix switch  # Build and activate
```

Nix uses the configured machine's canonical remote `nix` lock and does not create a repository `flake.lock`. If the lock cannot be downloaded, the command stops before building or activating. Check the lockfile service configuration, credentials, and connectivity before retrying; there is no local-lock fallback.

The source comes from `OUTFITTING_REPO` first, then a checkout saved by `setup --repo`. Without a checkout override, the manager refreshes its sparse source at `<stateRoot>/source`. An invalid saved checkout fails rather than silently switching sources. See [setup](/docs/cli/macos/setup/) for symlink collision handling.

## Homebrew and combined updates

`update brew` reconciles the managed `packages/macos/Brewfile`, upgrades Homebrew packages, and stores the observed inventory. `update all` runs the Nix switch followed by Homebrew and returns failure if either step fails.

Pass `--no-sync` to `brew` or `all` to keep inventory and lock changes local:

```bash
outfit update brew --no-sync
outfit update all --no-sync
```

Global Bun packages are updated by Bun itself:

```bash
bun update -g
```

`outfit update bun` is deprecated and prints this replacement. Windows package-manager commands are unavailable in the macOS build.
