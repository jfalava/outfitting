Any Linux profile may declare a Nix flake in `outfitting.json`; `setup` and `update nix` apply its Home Manager configuration. `init` only selects and validates the configured source. Flake pins are owned by the BYOR checkout.

## Manager

```bash
outfitting-manager update nix         # lists actions
outfitting-manager update nix build
outfitting-manager update nix test
outfitting-manager update nix dry
outfitting-manager update nix switch            # refresh source, build and activate
outfitting-manager update nix switch --no-refresh  # use the local source
```

Bare `update nix` only lists subcommands. Actions resolve the flake declared by the selected profile's BYOR contract. Linux uses the flake's checked-in `flake.lock`; actions refresh the selected source by default, while `--no-refresh` uses the validated published source already on disk. Refresh does not run `nix flake update`. `update all` runs `switch` when the selected profile declares a flake, then updates native packages.

## Shell helpers

Shared implementation: `system/common/zsh/hm-profile.inc.zsh`, loaded by the profile Zsh plugin.

```bash
hm-build     # build without activating
hm-test      # test-build without activating
hm-dry       # dry-run without activating
hm-switch    # build and activate
hm-update    # manager: switch only; native fallback may run nix flake update first
hm-rollback  # list generations
hm-clean     # remove old store paths
```

When `outfitting-manager` is on `PATH`, helpers call `update nix <action>`. Otherwise they run native `nix build` / `home-manager switch` (or `nix run … home-manager`).

For source selection, use a local checkout with root `outfitting.json` or a remote source declared in the state-root `byor.json`. See [BYOR](/docs/cli/byor/).
