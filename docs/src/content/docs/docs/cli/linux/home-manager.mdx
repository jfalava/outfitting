Any Linux profile may declare a Nix flake in `config.toml`; `nix` builds or activates its Home Manager configuration. `init` prepares and validates the configured source, while `apply` and `update` handle native package declarations and upgrades separately. Flake pins are owned by the source checkout.

## Manager

```bash
outfitting-manager nix                 # lists actions
outfitting-manager nix build
outfitting-manager nix test
outfitting-manager nix dry-run
outfitting-manager nix switch          # refresh source, build and activate
outfitting-manager nix switch --no-refresh  # use the local source
```

Bare `nix` only lists actions. Actions resolve the flake declared by the selected profile in `config.toml`. Linux uses the flake's checked-in `flake.lock`; actions refresh the selected source by default, while `--no-refresh` uses the validated published source already on disk. Refresh does not run `nix flake update`. Run `update` separately when you also want to upgrade native packages.

## Shell helpers

Shared implementation: `system/common/zsh/hm-profile.inc.zsh`, loaded by the profile Zsh plugin.

```bash
hm-build     # build without activating
hm-test      # test-build without activating
hm-dry       # dry-run without activating
hm-switch    # build and activate
hm-update    # manager: switch only; native fallback may run nix flake update first
hm-rollback  # list generations
hm-clean     # remove old store paths
```

When `outfitting-manager` is on `PATH`, helpers call `nix <action>`. Otherwise they run native `nix build` / `home-manager switch` (or `nix run … home-manager`).

For source selection, declare a local checkout or remote Git source in [config.toml](/docs/source-configuration/).
