The Nix-backed `oci-agents` and `ubuntu-wsl` profiles apply Home Manager during `init`, `setup`, and `update nix`. Both pin **Home Manager release-26.05** (with `nixos-26.05` nixpkgs), matching macOS and NixOS.

## Manager commands (same as macOS)

```bash
outfitting-manager update nix         # switch (default)
outfitting-manager update nix build   # Build without activating
outfitting-manager update nix test    # Test-build without activating
outfitting-manager update nix dry     # Dry-run without activating
outfitting-manager update nix switch  # Build and activate
```

`update nix` resolves the flake from `linux.profile` (`oci-agents` → `system/oci-agents#oci-agents`, `ubuntu-wsl` → `system/ubuntu-wsl#jfalava`), links `~/.config/home-manager`, builds the activation package, and activates it. Pass `--profile` to override the persisted profile. Unlike macOS, Linux uses the flake’s checked-in `flake.lock` (no remote lock pull).

## Zsh helpers

Zsh `hm-*` helpers call the manager when available and fall back to native Home Manager otherwise. Shared implementation: `system/common/zsh/hm-profile.inc.zsh`.

```bash
hm-build     # Build without activating
hm-test      # Test-build without activating
hm-dry       # Dry-run without activating
hm-switch    # Build and activate
hm-sync      # Alias for hm-switch
hm-update    # With the manager: switch only. Native fallback still runs nix flake update first.
hm-rollback  # List generations and show activation instructions
hm-clean     # Remove old Nix generations and store paths
```

The hosted installer uses the sparse source at `$HOME/.config/outfitting/source`. Set `OUTFITTING_REPO` or pass `--repo` at setup time to use another full checkout.

The OCI bootstrap also installs upstream harness binaries (including OpenCode v2 via `https://opencode.ai/v2/install`), sets the login shell to zsh, enables user lingering, starts `user@uid` when the session bus is missing, and starts Amp/T3/OpenCode units. Home Manager owns OpenCode config and the web unit; the real `opencode` binary is not a Nix package. The OCI Zsh plugin starts a local `ssh-agent` when `SSH_AUTH_SOCK` is missing (forwarded agents are left alone), auto-loads `~/.ssh/jfalava-gitAuth-elliptic` when the agent is empty, and exports `DBUS_SESSION_BUS_ADDRESS` for libsecret. Open a new SSH session after the first activation so the profile takes effect. Shared SSH config prefers that elliptic auth key for `github.com`.
