Nix-backed profiles (`ubuntu-wsl`, `oci-agents`) apply Home Manager during `setup` and `update nix`. `init` only prepares the local source. Pins match macOS: **Home Manager release-26.05** and **nixos-26.05**.

## Manager

```bash
outfitting-manager update nix         # lists actions
outfitting-manager update nix build
outfitting-manager update nix test
outfitting-manager update nix dry
outfitting-manager update nix switch  # build and activate
```

Bare `update nix` only lists subcommands. Actions resolve the flake from `linux.profile`:

| Profile      | Flake                          |
| ------------ | ------------------------------ |
| `ubuntu-wsl` | `system/ubuntu-wsl#jfalava`    |
| `oci-agents` | `system/oci-agents#oci-agents` |

Linux uses the flake’s checked-in `flake.lock` (no remote lock pull). Pass `--profile` on the action subcommands when you need to override the persisted profile.

## Shell helpers

Shared implementation: `system/common/zsh/hm-profile.inc.zsh`, loaded by the profile Zsh plugin.

```bash
hm-build     # build without activating
hm-test      # test-build without activating
hm-dry       # dry-run without activating
hm-switch    # build and activate
hm-update    # manager: switch only; native fallback may run nix flake update first
hm-rollback  # list generations
hm-clean     # remove old store paths
```

When `outfitting-manager` is on `PATH`, helpers call `update nix <action>`. Otherwise they run native `nix build` / `home-manager switch` (or `nix run … home-manager`).

Sparse source default: `$HOME/.config/outfitting/source`. Override with `OUTFITTING_REPO` or `--repo` at setup time.
