`apply` reconciles configured package declarations. It installs missing declared packages; with `--prune`, it may remove only packages that Outfitting can prove it owns for the active profile. It does not upgrade unrelated installed software. Run [`init`](/docs/cli/init/) first to prepare and validate the configured source.

Without `--prune`, apply only installs missing declared packages. Manually installed packages and packages owned by inactive profiles are protected.

Legacy inventory without installation ownership is never enough evidence to prune. Linux previews the package manager's removal plan and refuses unexpected removals; it uses plain `apt remove` or `pacman -R`, never dependency autoremove.

## macOS

```bash
outfitting-manager apply
outfitting-manager apply --profile workstation --no-refresh
```

macOS applies only the selected Brewfile. It does not activate Nix; use [`nix switch`](/docs/cli/nix/) for nix-darwin.

## Windows

```powershell
outfitting-manager apply
outfitting-manager apply --profile base,dev --winget-only
outfitting-manager apply --prune --yes
```

Windows options are `--profile <profiles>`, `--winget-only`, `--prune`, and `--yes`. `--yes` accepts the displayed installation and removal plan without prompting. See [source configuration](/docs/source-configuration/) for bundle composition. Apply changes local machine state only; it does not upload state. Run [`sync push`](/docs/cli/sync/#sync-push) explicitly when you want to publish it.

## Linux

```bash
outfitting-manager apply
outfitting-manager apply --no-refresh
outfitting-manager apply --package-manager apt --profile debian-minimal
outfitting-manager apply --package-manager pacman --prune --yes
outfitting-manager apply --offline
outfitting-manager apply --if-configured
```

Linux detects apt or pacman from the host by default. Select one explicitly with `--package-manager apt|pacman`. Other options are `--profile <profile>`, `--prune`, `--offline`, `--yes`, and `--no-refresh`. `--if-configured` skips the operation only when the selected profile declares neither native package manager; it is useful in bootstrap scripts for profiles that declare only Nix. Linux refreshes the configured source by default. `--no-refresh` and `--offline` require a previously validated remote snapshot; use `init` to populate one before running them.

Offline apt installs require cached package payloads. Offline pacman refuses missing-package installs; it can inspect already-satisfied declarations and perform a safe prune without downloads.

## Platform differences

| Platform | Forms                                                                                 | Difference                                                                |
| -------- | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| macOS    | `apply [--profile <profile>] [--no-refresh]`                                          | Reconciles the Brewfile only; Nix activation is `nix switch`.              |
| Windows  | `apply [--profile <profiles>] [--winget-only] [--prune] [--yes]`                     | Profiles are comma-composable; apply never uploads state.                 |
| Linux    | `apply [--package-manager <manager>] [--profile <profile>] [--prune] [--offline]` | One profile is active at a time; `--offline` prevents package downloads. |
