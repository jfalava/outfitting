`apply` reconciles package presence from the active profile. It is available on Windows and Linux; macOS uses `setup` for declarative activation. Linux refreshes the active profile source before planning changes.

On Linux, pass `--no-refresh` to use the selected local source without fetching remote changes, or `--offline` to skip source refresh and prohibit network-backed package-manager work.

With `--no-refresh`, declarations come from `OUTFITTING_REPO` or the saved checkout first, then materialized manifests, then the HTTP cache without making a request. Run [`init`](/docs/cli/init/) to refresh cached declarations separately, or let Linux `apply` update the active source as part of reconciliation.

Without `--prune`, apply only installs missing declared packages. With `--prune`, it may remove only packages that Outfitting installed for the active profile and that profile no longer declares. Manually installed packages and packages owned by inactive profiles are protected.

Legacy inventory without installation ownership is never enough evidence to prune. Linux previews the package manager's removal plan and refuses unexpected removals; it uses plain `apt remove` or `pacman -R`, never dependency autoremove.

## Windows

```powershell
outfitting-manager apply
outfitting-manager apply --profile base,dev --winget-only
outfitting-manager apply --prune --yes
```

Windows options are `--profile <profiles>`, `--winget-only`, `--prune`, and `--yes`. `--yes` accepts the displayed installation and removal plan without prompting. See [Profiles](/docs/source-configuration/#profiles) for bundle composition. Apply changes local machine state only; it does not upload state. Run [`sync push`](/docs/cli/sync/#sync-push) explicitly when you want to publish it.

## Linux

```bash
outfitting-manager apply all
outfitting-manager apply all --no-refresh
outfitting-manager apply apt --profile ubuntu-wsl
outfitting-manager apply pacman --prune --yes
outfitting-manager apply all --offline
```

Choose `all`, `apt`, or `pacman`. Linux options are `--profile <profile>`, `--prune`, `--offline`, `--yes`, and `--no-refresh`. Linux refreshes the configured active profile by default; `--no-refresh` requires an already available local source when switching profiles, so use `init` or `setup` to select and populate a different profile.

Offline apt installs require cached package payloads. Offline pacman refuses missing-package installs; it can inspect already-satisfied declarations and perform a safe prune without downloads.

## Platform differences

| Platform | Forms                                                            | Difference                                                               |
| -------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------ |
| macOS    | Not available                                                    | Use `setup` to activate local Nix and Homebrew declarations.             |
| Windows  | `apply [--profile <profiles>] [--winget-only] [--prune] [--yes]` | Profiles are comma-composable; apply never uploads state.                |
| Linux    | `apply` with `all`, `apt`, or `pacman`, plus the listed options  | One profile is active at a time; `--offline` prevents package downloads. |
