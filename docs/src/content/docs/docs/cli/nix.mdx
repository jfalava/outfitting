`nix` owns Nix build and activation actions on macOS and Linux. It is separate from native package [`update`](/docs/cli/update/) and declaration [`apply`](/docs/cli/apply/). A bare `nix` command lists actions and does not run one.

```bash
outfitting-manager nix build
outfitting-manager nix test
outfitting-manager nix dry-run
outfitting-manager nix switch
```

Each action accepts `--profile <profile>`, `--no-refresh`, and `--no-push`. Linux actions also accept `--if-configured`, which skips when the selected profile has no Nix flake; Linux bootstrap scripts use it because Nix is optional. The profile defaults to the selection in `config.toml`. `--no-refresh` reuses the configured local source or previously validated remote snapshot. Successful actions publish related Nix lock state by default; `--no-push` keeps it local.

On macOS, `switch` builds and activates nix-darwin. On Linux, it builds and activates the selected Home Manager profile. Linux Nix profiles use their checked-in `flake.lock`; source refresh does not run `nix flake update`.
