## Prerequisites

- You may need to install or update [WinGet](https://learn.microsoft.com/en-us/windows/package-manager/winget/#install-winget).
- Most regular Windows machines already have it, but it can be outdated.
- Update WinGet from the [Microsoft Store listing](https://apps.microsoft.com/detail/9NBLGGH4NNS1) if needed.
- Run the main installer from an elevated PowerShell session. OpenSSH, its firewall rule, and machine-level registry tweaks need elevation to complete.
- If PowerShell blocks the command, run:

```powershell
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
```

- WinGet and Microsoft Store package installations must use an explicit profile. There is no default profile.

## View Available Profiles

```powershell
irm win.jfa.dev | iex
```

## WinGet Package Installation

The main installer bootstraps the release binary, then asks `outfitting-manager` to fetch and install the selected WinGet profiles. Package reconciliation does not clone the repository; it reads the selected manifests from GitHub and writes the local Windows lock.

Use elevated PowerShell for the full installer:

```powershell
# Single profile
irm win.jfa.dev/base | iex
irm win.jfa.dev/dev | iex

# Multiple profiles combined
irm win.jfa.dev/base+dev+gaming | iex
irm win.jfa.dev/dev+gaming+qol | iex
```

Available WinGet profiles:

- `base`: Core packages, runtimes, and utilities
- `dev`: Development tools and environments
- `gaming`: Gaming platforms and tools
- `work`: Work-related applications
- `qol`: Quality of life improvements
- `network`: Network tools and utilities

The installer also:

- Installs the `PSReadLine PowerShell` module for the current user.
- Fetches the selected package manifests and the PowerShell profile sparsely from the configured GitHub source. A full repository checkout is not required on Windows.
- Downloads the latest Windows x64 outfitting-manager zip and its `.sha256` file, verifies the archive checksum, extracts `outfitting-manager.exe`, and installs it under `%USERPROFILE%\.local\bin`.
- Downloads and installs the latest `PowerShell/Win32-OpenSSH` server when it is missing, starts `sshd`, configures automatic startup, and creates the inbound TCP port 22 firewall rule.
- Links the PowerShell, VS Code PowerShell, and Windows PowerShell profile entry points to the cached `dotfiles/Microsoft.PowerShell_profile.ps1`. Existing profiles are backed up with a timestamp before replacement; later `outfit sync` refreshes the cached source.
- Discovers .reg files under [system/windows/registry](https://github.com/jfalava/outfitting/tree/main/system/windows/registry) and interactively offers to import them. Choose A for all (the default), N for none, or R to review each tweak.

The profile links use Windows symbolic links. Enable Windows Developer Mode or run the installer with the required elevation for those links to be created.

## Microsoft Store Package Installation

Microsoft Store packages require the /msstore/ prefix in the URL.

```powershell
# Single profile
irm win.jfa.dev/msstore/msstore-base | iex

# Multiple profiles combined
irm win.jfa.dev/msstore/msstore-base+msstore-gaming | iex
irm win.jfa.dev/msstore/msstore-base+msstore-gaming+msstore-qol | iex
```

Available Microsoft Store profiles:

- `msstore-base`: Core Microsoft Store apps
- `msstore-dev`: Development-related Store apps
- `msstore-gaming`: Gaming-related Store apps
- `msstore-work`: Work-related Store apps
- `msstore-qol`: Quality of life Store apps

Correct format:

```powershell
irm win.jfa.dev/msstore/<profile>+<profile> | iex
```

## Outfitting manager

The main Windows installer downloads the latest Windows x64 outfitting-manager zip, verifies its SHA-256 checksum, extracts `outfitting-manager.exe`, and installs it to:

```text
%USERPROFILE%\.local\bin\outfitting-manager.exe
```

The separate [post-install script](/docs/windows/post-install/) silently performs the same checksum-verified download as a best-effort fallback when the executable is missing. It suppresses manager download errors and does not block its other tasks. The manager is a release binary; these scripts do not create a manager symlink or build it from the repository. The linked PowerShell profile provides `outfit` as an alias for `outfitting-manager`.

The installer does not persist `%USERPROFILE%\.local\bin` in the user PATH. The linked PowerShell profile adds it when a new session starts. Open a new PowerShell session or reload the profile with `. $PROFILE` before running the manager.

## Bun Global Packages

The `base` WinGet profile installs Bun as `Oven-sh.Bun`. Windows has no `/bun` installer route. `packages/bun.txt` is cached by `outfitting-manager setup`, but it is not a desired-state manifest for Windows global packages.

After Bun is installed, update the global packages that are already present:

```powershell
outfitting-manager update bun
```

`update bun` fails when Bun is missing. `update all` skips the Bun step when Bun is not installed.

## Scoop reconciliation and unified lock

The repository-owned `packages/windows/scoop.txt` is part of the Windows baseline. `outfit sync` fetches it without requiring a full local checkout, reconciles buckets and packages, and records the result in the unified `windows.lock.json`. Normal sync preserves manually installed packages; use `--clean` to remove tracked packages outside the selected baseline. The installer uses `--winget-only` until the post-install step bootstraps Scoop.

```powershell
outfit setup
outfit sync
outfit sync --profile base,dev --clean
```

Manual package installs are tracked through the CLI, while native `winget` and `scoop` remain available for unmanaged packages:

```powershell
outfit winget install Git.Git
outfit scoop install extras/fzf
```

## Registry Tweaks Only

Runs only the registry tweak installer (no WinGet or Microsoft Store packages).

```powershell
irm win.jfa.dev/registry | iex
```
