## Prerequisites

- You may need to install or update [WinGet](https://learn.microsoft.com/en-us/windows/package-manager/winget/#install-winget).
- Most regular Windows machines already have it, but it can be outdated.
- Update WinGet from the [Microsoft Store listing](https://apps.microsoft.com/detail/9NBLGGH4NNS1) if needed.
- If elevation issues occur, run:

```powershell
Set-ExecutionPolicy -ExecutionPolicy Bypass -Scope Process
```

- All package installations must be explicitly specified. There is no default installation.

## View Available Profiles

```powershell
irm win.jfa.dev | iex
```

## WinGet Package Installation

All commands require elevated PowerShell.

```powershell
# Single profile
irm win.jfa.dev/base | iex
irm win.jfa.dev/dev | iex

# Multiple profiles combined
irm win.jfa.dev/base+dev+gaming | iex
irm win.jfa.dev/dev+gaming+qol | iex
```

Available WinGet profiles:

- `base`: Core packages, runtimes, and utilities
- `dev`: Development tools and environments
- `gaming`: Gaming platforms and tools
- `work`: Work-related applications
- `qol`: Quality of life improvements
- `network`: Network tools and utilities

## Microsoft Store Package Installation

Microsoft Store packages require the `/msstore/` prefix in the URL.

```powershell
# Single profile
irm win.jfa.dev/msstore/msstore-base | iex

# Multiple profiles combined
irm win.jfa.dev/msstore/msstore-base+msstore-gaming | iex
irm win.jfa.dev/msstore/msstore-base+msstore-gaming+msstore-qol | iex
```

Available Microsoft Store profiles:

- `msstore-base`: Core Microsoft Store apps
- `msstore-dev`: Development-related Store apps
- `msstore-gaming`: Gaming-related Store apps
- `msstore-work`: Work-related Store apps
- `msstore-qol`: Quality of life Store apps

Correct format:

```powershell
irm win.jfa.dev/msstore/<profile>+<profile> | iex
```

## Outfitting manager

The main Windows installer downloads the latest Windows x64 `outfitting-manager` release and its SHA-256 checksum to:

```text
%USERPROFILE%\.local\bin\outfitting-manager.exe
```

The post-install script silently checks that path and makes the same checksum-verified download as a best-effort fallback when the executable is missing. It suppresses download errors and does not block the other post-install tasks. The manager is a release binary; these scripts do not create a manager symlink or build it from the repository.

The PowerShell profile adds `%USERPROFILE%\.local\bin` to the session `PATH`. Lockfile inventory uploads performed by `Update-All` check for outfitting-manager on `PATH`. If it is unavailable, the affected upload is skipped with a warning and `Update-All` continues.

## Scoop inventory

The repository-owned `packages/x64-windows/scoop.txt` is the source of truth for directly installed Scoop packages. Every `Update-All` run must reconcile the local installation to that manifest; missing Scoop is an error rather than a skipped step. After reconciliation it stores a stable, versioned `scoop-inventory` snapshot through `outfitting-manager`, including resolved dependencies and installed versions.

Run `Save-OutfittingScoopInventory` to capture state without reconciling first.

## Registry Tweaks Only

Runs only the registry tweak installer (no WinGet or Microsoft Store packages).

```powershell
irm win.jfa.dev/registry | iex
```

## Post-install and licensed fonts

Run the post-install script after the main installer. It performs post-install work, installs the public fonts listed in `fonts/fontget.txt` via FontGet, and extracts the licensed fonts to `%USERPROFILE%\Downloads\fonts`. You can then choose whether to install the licensed fonts manually. If your account does not have access to the licensed font archive, that optional step is skipped without failing the rest of the script.

```powershell
irm win.jfa.dev/post-install | iex
```
