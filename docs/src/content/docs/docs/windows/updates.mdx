## Manager setup

The manager keeps configuration, manifest caches, and materialized manifests under `%USERPROFILE%\.config\outfitting` by default. It fetches the manifests from the repository's raw content; it does not clone or pull the monorepo.

Run setup once, or run it again when changing the machine id or manifest source. The default Windows machine id is `<username>:x86_64-windows`:

```powershell
outfitting-manager setup
outfitting-manager setup --machine-id jfalava:x86_64-windows
```

The Windows setup manifests are `packages/windows/scoop.txt` and `packages/bun.txt`. Setup caches both files in the state root; only `scoop.txt` is reconciled as desired package state. `update bun` updates global packages already installed by Bun. Use `--no-fetch` when only the state root and config should be created.

For a different manifest source, pass a raw GitHub base URL without the ref and an explicit Git ref:

```powershell
outfitting-manager setup `
  --manifest-base-url "https://raw.githubusercontent.com/jfalava/outfitting" `
  --manifest-ref main
```

## Repository-managed configuration

The installer stores the repository path in `%USERPROFILE%\.config\outfitting\repo-path`. If `OUTFITTING_REPO` is set, it takes precedence; otherwise the default is `%USERPROFILE%\.config\outfitting\repo`.

Pull the latest repository changes using the configured path:

```powershell
$repoPathFile = Join-Path $HOME ".config\outfitting\repo-path"
$repoPath = if ($env:OUTFITTING_REPO) {
    $env:OUTFITTING_REPO
} elseif (Test-Path -LiteralPath $repoPathFile -PathType Leaf) {
    (Get-Content -LiteralPath $repoPathFile -Raw).Trim()
} else {
    Join-Path $HOME ".config\outfitting\repo"
}
Set-Location $repoPath
git pull

```

The PowerShell profile entry points remain symbolic links to the repository-owned profile, so pulling updates the linked source directly. Open a new PowerShell session after pulling, or reload the profile in the current session:

```powershell
. $PROFILE
```

The profile also provides the reload alias:

```powershell
reload
```

## Packages and inventories

The manager is the Windows package-update path:

```powershell
outfitting-manager update winget
outfitting-manager update scoop
outfitting-manager update bun
outfitting-manager update all
```

`update winget` upgrades all installed WinGet packages and stores the exported `winget` state. `update scoop` reconciles `packages/windows/scoop.txt`, updates packages, and stores `scoop-inventory`. `update bun` updates global Bun packages and stores `bun-global-inventory`.

`update all` runs `winget → scoop → bun`, then stores the successful inventories. It continues after a failed step and exits nonzero if any update or inventory step fails. When Bun is absent, `update all` skips it; explicit `update bun` fails. Add `--no-sync` to any update command to skip inventory uploads.

The existing PowerShell `Update-All` profile function remains available as a legacy full update path. It still runs WinGet, Scoop, Bun globals, PowerShell module updates, and a WinGet inventory export; it is not a modules-only command. Prefer the manager for package updates and inventory snapshots. PowerShell continues to own session environment and `PATH` setup.

The manager stores uploads under its configured machine id, normally `<username>:x86_64-windows`. The legacy profile functions in this repository still use `jfalava:x64-windows`; set `--machine-id` explicitly if those snapshots must share one remote record.

Configure the lockfiles Worker before the first upload if the machine has not been provisioned:

```powershell
outfitting-manager sync configure-worker
outfitting-manager sync configure-token
```

Use the compiled release binary for self-upgrades. Running `upgrade` from Bun source is rejected; see [CLI upgrade](/docs/cli/upgrade/) for the Windows replacement behavior.
