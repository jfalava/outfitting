The Windows manager stores configuration, fetched manifests, and `windows.lock.json` under `%LOCALAPPDATA%\outfitting`. You can set `OUTFITTING_STATE_ROOT` to choose a different directory. State from older default locations is not copied automatically.

## Upgrade installed packages (`update`)

Use `update` to upgrade existing software through one selected package manager. It only upgrades packages you already have; to install newly declared profile packages, use [`apply`](#apply-profile-changes-apply).

```powershell
# Upgrade WinGet packages
outfitting-manager update --package-manager winget

# Upgrade Scoop packages without pushing lockfile changes
outfitting-manager update --package-manager scoop --no-push
```

Windows requires `--package-manager winget|scoop`. Each command upgrades only the selected manager and records its own state. To upgrade both, run both commands separately. State is pushed by default; pass `--no-push` to keep it local.

## Apply profile changes (`apply`)

When you add new packages to your profile manifests, run `apply` to install them:

```powershell
# Install missing packages for selected profiles
outfitting-manager apply --profile base,dev

# Apply only WinGet packages
outfitting-manager apply --profile base,dev --winget-only
```

## Update Outfitting and dependencies

- **Outfitting CLI:** Update the compiled manager binary with [`self-update`](/docs/cli/self-update/).
- **Bun packages:** Update global Bun packages with `bun update -g`.

For the complete command reference, see the [Windows CLI reference](/docs/cli/windows/).
