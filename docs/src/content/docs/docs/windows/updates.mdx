The Windows manager stores configuration, fetched manifests, and `windows.lock.json` under `%USERPROFILE%\.config\outfitting`. It does not need a monorepo checkout.

Use the [Windows CLI reference](/docs/cli/windows/) for the complete workflows:

1. Run [config](/docs/cli/windows/config/) when the repository or route map changes.
2. Run [setup](/docs/cli/windows/setup/) for initialization and first application.
3. Run [sync](/docs/cli/windows/sync/) to reconcile selected profiles.
4. Run [update](/docs/cli/windows/update/) to upgrade installed packages.

Typical maintenance:

```powershell
outfit sync
outfit update all
bun update -g
```

Use [remote lockfiles](/docs/cli/lockfiles/) for direct Worker transport and [CLI upgrade](/docs/cli/upgrade/) for self-updating the compiled manager.
