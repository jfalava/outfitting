The `api` package is the Cloudflare Worker used by `outfitting-manager`. It stores generated state that is not committed to Git, so it can be restored after rebuilding or replacing a machine.

Public URL (via the edge router): `https://outfitting.jfa.dev/api`.

KV holds content-addressed blobs; D1 holds searchable metadata. See [storage](/docs/manager/architecture#storage) for the storage model.

## Deploy

Infrastructure lives in `iac/` (Alchemy). Names default to `outfitting-*` and are overridable — see [Provision](/docs/manager/provision).

```bash
bun install
cp iac/.env.example iac/.env   # set OUTFITTING_LOCKFILES_TOKEN if provisioning
CI=1 bun run deploy -- --yes --adopt

# Or: bun run cli/index.ts provision [--no-docs] [--api-name outfitting-api-dev] …
```

Default stack owns:

- `outfitting-api` (private) — this worker
- `outfitting-docs` + static assets (private; omit with `--no-docs`)
- `outfitting-installer` (private)
- `outfitting-router` — sole public entry on the configured domain and installer hosts

Existing D1 (`outfitting-lockfiles`), KV, R2, and the Secrets Store secret are adopted when those names match. Configure the CLI base URL as `https://<router-domain>/api` — see [manager CLI](/docs/manager/cli#configure-lockfile-storage).

## HTTP API

Every request requires `Authorization: Bearer <OUTFITTING_LOCKFILES_TOKEN>`.

Paths below are relative to the API worker. Through the router they are prefixed with `/api` (the router strips that prefix before forwarding).

| Method   | Route                               | Result                                                |
| -------- | ----------------------------------- | ----------------------------------------------------- |
| `PUT`    | `/lockfiles/:machine/:kind`         | Stores/promotes the body and returns `{ hash, size }` |
| `GET`    | `/lockfiles/:machine/:kind`         | Returns the latest raw content as text                |
| `GET`    | `/lockfiles/:machine/:kind/history` | Returns `{ hash, size, created_at }[]`, newest first  |
| `GET`    | `/lockfiles/:machine`               | Returns a sorted JSON array of tracked kinds          |
| `DELETE` | `/lockfiles/:machine/:kind/:hash`   | Deletes one D1 row                                    |

Public equivalents: `https://outfitting.jfa.dev/api/lockfiles/...`.

`PUT` accepts an optional standard `If-Match: "<sha256>"` header. The D1 promotion and head update are atomic; a stale expected hash returns HTTP 412 without advancing the head. Deleting the current head returns HTTP 409.

## Homebrew inventories

Homebrew does not create or support lockfile. The macOS integration records a sorted, versioned inventory after successful Homebrew sync and upgrade operations while keeping the committed Brewfile as desired state.
