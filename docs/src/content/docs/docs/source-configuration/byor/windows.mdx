Outfitting lets you configure Windows hosts using your own Git repository. You can define custom profiles and file paths in an `outfitting.json` file at the root of your repo, or use hosted remote manifests.

## Define custom profiles (`outfitting.json`)

Add an `outfitting.json` file to the root of your repository. In Windows, you can define shared settings (such as Scoop packages or PowerShell profiles) as well as individual WinGet profiles:

```json
{
  "schema": 1,
  "windows": {
    "defaultProfiles": ["base", "dev"],
    "scoop": { "manifest": "packages/windows/scoop.txt" },
    "powershell": { "path": "dotfiles/Microsoft.PowerShell_profile.ps1" },
    "fonts": { "manifest": "fonts/fontget.txt" },
    "registry": { "path": "system/windows/registry" }
  },
  "profiles": {
    "base": {
      "windows": {
        "winget": { "manifest": "packages/windows/base.txt" }
      }
    },
    "dev": {
      "windows": {
        "winget": { "manifest": "packages/custom/dev-winget.txt" }
      }
    }
  }
}
```

### Configuration breakdown

- **Top-level `windows` (optional):** Defines shared settings used across all profiles:
  - `defaultProfiles`: Profile list to apply when `--profile` is not specified. Defaults to all profiles containing a WinGet manifest.
  - `scoop.manifest`: Path to a Scoop package list.
  - `powershell.path`: Path to a PowerShell profile script to link into user profile locations.
  - `fonts.manifest`: Path to a font manifest.
  - `registry.path`: Path to a directory of registry scripts.
- **`profiles.<name>.windows`:** Defines an individual profile. Each Windows profile must specify a `winget.manifest` pointing to a non-empty WinGet package list.

### Profile rules

- **Composable profiles:** Unlike Linux and macOS, Windows profiles combine together. You can pass multiple comma-separated profiles (e.g. `--profile base,dev`).
- **Path safety:** All paths are relative to your repository root and cannot traverse outside it.
- **Multi-platform:** The same file can define profiles for Linux and macOS. See [BYOR for Linux](/docs/source-configuration/byor/linux/) and [BYOR for macOS](/docs/source-configuration/byor/macos/).

## Validate and apply

### 1. Validate your configuration

Check your configuration file and verify that all referenced paths exist:

```powershell
outfitting-manager validate --repo C:\src\my-machine-config --profile base,dev
```

If `outfitting.json` defines profiles for multiple platforms, add `--platform windows`.

### 2. Initialize and apply

Once validated, run `setup` or `apply` against your local checkout:

```powershell
# Prepare state and cache manifests
outfitting-manager init --repo C:\src\my-machine-config --profile base,dev

# Install missing packages and apply configuration
outfitting-manager apply --profile base,dev
```

You can also set the `OUTFITTING_REPO` environment variable instead of passing `--repo`.

## Remote repositories (`byor.json`)

If your repository is hosted on GitHub or GitHub Enterprise and you do not want to commit an `outfitting.json` file into it, use the interactive BYOR wizard:

```powershell
outfitting-manager byor
```

The wizard prompts for:
- Repository URL and git ref (branch, tag, or commit).
- Profile name and platform (`windows`).
- Winget manifest path.
- Any additional files outside the manifest directory.

This writes a local profile map to `~/.config/outfitting/byor.json`. Manifests are fetched using raw HTTPS (for public GitHub) or `gh api` (for GitHub Enterprise).

After running `byor`, initialize or apply your profile:

```powershell
outfitting-manager init
outfitting-manager setup
```

See the [`byor` CLI reference](/docs/cli/byor/) for command flags.

## Hosted sources and legacy routes

If you don't have a local checkout or an `outfitting.json` file, Windows can fetch manifests from a hosted repository using route templates stored in `config.json`:

```powershell
outfitting-manager config `
  --repo https://github.com/example/my-machine-config `
  --ref main
```

These default routes are used when no `outfitting.json` is present:

| Route | Default path |
| --- | --- |
| `wingetProfilePath` | `packages/windows/{profile}.txt` |
| `scoopPath` | `packages/windows/scoop.txt` |
| `powershellProfilePath` | `dotfiles/Microsoft.PowerShell_profile.ps1` |
| `fontListPath` | `fonts/fontget.txt` |
| `registryPath` | `system/windows/registry` |

See [Windows config](/docs/cli/windows/config/) for more options.
