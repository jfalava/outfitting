## Choose a source

Windows consumes cached manifests rather than a local checkout. Configure a GitHub repository or raw-compatible source and its routes with the Windows config command:

```powershell
outfitting-manager config `
  --repo https://github.com/example/my-machine-config `
  --ref main
```

See [Windows config](/docs/cli/windows/config/) for route and default-profile options. The equivalent environment variables are `OUTFITTING_MANIFEST_BASE_URL` and `OUTFITTING_MANIFEST_REF`.

## Repository schema

Windows uses repository-relative routes stored in `config.json`:

| Route                   | Default                                     |
| ----------------------- | ------------------------------------------- |
| `wingetProfilePath`     | `packages/windows/{profile}.txt`            |
| `scoopPath`             | `packages/windows/scoop.txt`                |
| `powershellProfilePath` | `dotfiles/Microsoft.PowerShell_profile.ps1` |
| `fontListPath`          | `fonts/fontget.txt`                         |
| `registryPath`          | `system/windows/registry`                   |

The WinGet route must contain `{profile}`. Routes cannot escape the repository, and profile names may contain only letters, numbers, `.`, `_`, or `-`. `defaultProfiles` selects the WinGet profiles used on a new machine. Windows setup caches these routes under the state root before applying packages and the PowerShell profile.
