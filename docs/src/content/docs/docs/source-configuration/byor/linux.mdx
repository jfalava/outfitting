Outfitting lets you configure Linux hosts using your own Git repository. You can define custom profiles in an `outfitting.json` file at the root of your repo, or follow Outfitting's built-in profile layout.

## Define custom profiles (`outfitting.json`)

To use your own repository structure, add an `outfitting.json` file to the root of your repository. You can choose any profile names you like, and configure `apt`, `pacman`, `nix`, or any combination of them for each profile:

```json
{
  "schema": 1,
  "profiles": {
    "nix-server": {
      "linux": {
        "nix": {
          "flake": "system/server",
          "attribute": "homeConfigurations.server.activationPackage"
        }
      }
    },
    "debian-minimal": {
      "linux": {
        "apt": { "manifest": "packages/debian/minimal.txt" }
      }
    }
  }
}
```

### Configuration rules

- **Profile exclusivity:** Linux activates one profile at a time (e.g. `--profile debian-minimal`). Selecting a profile replaces the active one rather than combining with it.
- **Backend combinations:** A single profile can combine `apt` or `pacman` manifests with a `nix` flake, or use only one backend.
- **Path safety:** Manifest and flake paths are relative to your repository root and cannot traverse outside it.
- **Multi-platform:** The same `outfitting.json` can also define profiles for Windows and macOS. See [BYOR for Windows](/docs/source-configuration/byor/windows/) and [BYOR for macOS](/docs/source-configuration/byor/macos/).

## Validate and apply

### 1. Validate your configuration

Test your repository structure without installing packages or touching machine state:

```bash
outfitting-manager validate \
  --repo ~/src/my-machine-config \
  --profile debian-minimal
```

If `outfitting.json` defines profiles for multiple platforms, add `--platform linux`.

### 2. Initialize or apply

Once validated, point `init` or `setup` to your repository:

```bash
# Prepare state without modifying installed packages
outfitting-manager init \
  --repo ~/src/my-machine-config \
  --profile debian-minimal

# Install declared packages and apply Nix state
outfitting-manager setup \
  --repo ~/src/my-machine-config \
  --profile debian-minimal
```

You can also set the `OUTFITTING_REPO` environment variable instead of passing `--repo` every time.

## Remote repositories (`byor.json`)

If your repository is hosted on GitHub or GitHub Enterprise and you do not want to commit an `outfitting.json` file into it, you can map your repository using the interactive BYOR wizard:

```bash
outfitting-manager byor
```

The wizard prompts for:
- Repository URL and git ref (branch, tag, or commit).
- Profile name and platform (`linux`).
- Manifest paths (`apt` or `pacman`) and/or Nix flake directory.
- Any files outside your flake directory.

This writes a local profile map to `~/.config/outfitting/byor.json`. Outfitting fetches manifests and complete Nix flake trees using raw HTTPS (for public GitHub) or `gh api` (for GitHub Enterprise).

After running `byor`, initialize or apply your profile:

```bash
outfitting-manager init --profile debian-minimal
outfitting-manager setup --profile debian-minimal
```

See the [`byor` CLI reference](/docs/cli/byor/) for command flags.

## Built-in repository layout

If your repository does not contain an `outfitting.json`, Outfitting looks for its built-in profiles: `generic-linux`, `ubuntu-wsl`, or `oci-agents`. This layout is also used when pulling from a remote hosted source via `--manifest-base-url`.

Nix-backed built-in profiles expect these shared paths:

```text
system/common/zsh.nix
system/common/zsh/outfitting.plugin.zsh
system/common/zsh/hm-profile.inc.zsh
system/common/dotfiles.nix
dotfiles/ssh.config
packages/common/programs.nix
packages/common/packages.nix
packages/common/opencode-mcp.nix
```

In addition, each built-in profile requires its specific manifests and files:

| Profile | Package manifest | Nix configuration |
| --- | --- | --- |
| `generic-linux` | `packages/linux/generic-linux.txt` | None (native packages only). |
| `oci-agents` | `packages/linux/oci-agents.txt` | `packages/oci-agents/packages.nix` and `system/oci-agents/{agent-guidance.md,agents.nix,bootstrap.sh,flake.lock,flake.nix,home.nix,zsh/oci-agents.plugin.zsh}`. Flake must export `homeConfigurations.oci-agents`. |
| `ubuntu-wsl` | `packages/ubuntu-wsl/apt.txt` | `packages/ubuntu-wsl/packages.nix` and `system/ubuntu-wsl/{base.nix,bootstrap.sh,flake.lock,flake.nix,zsh/wsl.plugin.zsh}`. Flake must export `homeConfigurations.jfalava`. |

To use a hosted repository without a local checkout:

```bash
outfitting-manager setup \
  --profile generic-linux \
  --manifest-base-url https://raw.githubusercontent.com/example/my-machine-config \
  --manifest-ref main
```
