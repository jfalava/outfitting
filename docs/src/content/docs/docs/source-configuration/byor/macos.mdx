Outfitting lets you configure macOS hosts using your own Git repository. You can declare custom profiles with your own nix-darwin flake, Brewfile, and font paths in an `outfitting.json` file at the root of your repo, or use Outfitting's built-in macOS layout.

## Define custom profiles (`outfitting.json`)

Add an `outfitting.json` file to the root of your repository. Under `profiles`, define one or more profile names with their macOS configuration:

```json
{
  "schema": 1,
  "profiles": {
    "workstation": {
      "macos": {
        "nix": {
          "flake": "system/work",
          "attribute": "darwinConfigurations.workstation.system",
          "darwin": "system/work/darwin.nix"
        },
        "brewfile": "packages/work/Brewfile",
        "fonts": { "manifest": "fonts/fontget.txt" },
        "paths": ["system/work/home.nix"]
      }
    }
  }
}
```

### Configuration breakdown

- **`nix.flake`:** Path to the directory containing your `flake.nix`. The flake must output `darwinConfigurations`.
- **`nix.attribute`:** Dot-separated Nix attribute path to activate (e.g. `darwinConfigurations.workstation.system`).
- **`nix.darwin` (optional):** Path to the darwin configuration module. Defaults to `<flake>/darwin.nix`.
- **`brewfile` (optional):** Path to a Homebrew Brewfile. If omitted, Homebrew bundle activation is skipped.
- **`fonts.manifest` (optional):** Path to a font manifest.
- **`paths` (optional):** Extra files or directories needed during nix-darwin evaluation.

### Profile rules

- **Profile exclusivity:** macOS selects one profile at a time. If you declare multiple macOS profiles, select one with `--profile <name>`.
- **Path safety:** All paths are relative to your repository root and cannot traverse outside it.
- **Multi-platform:** The same `outfitting.json` can also define profiles for Linux and Windows. See [BYOR for Linux](/docs/source-configuration/byor/linux/) and [BYOR for Windows](/docs/source-configuration/byor/windows/).

## Validate and apply

### 1. Validate your configuration

Verify your configuration and ensure that the flake, darwin module, and optional files exist:

```bash
outfitting-manager validate \
  --repo ~/src/my-machine-config \
  --profile workstation
```

If `outfitting.json` defines profiles for multiple platforms, add `--platform macos`.

### 2. Initialize and setup

Once validated, apply the profile:

```bash
# Prepare state without modifying the system
outfitting-manager init --repo ~/src/my-machine-config

# Activate nix-darwin and install missing Brewfile packages
outfitting-manager setup --repo ~/src/my-machine-config
```

You can also set the `OUTFITTING_REPO` environment variable instead of passing `--repo`. When using BYOR, Outfitting works directly from your local repository checkout without downloading monorepo sparse sources.

## Default repository layout

When no `outfitting.json` macOS profile is present, Outfitting expects its default file layout:

```text
system/macos/flake.nix
system/macos/darwin.nix
system/macos/home.nix
system/macos/zsh/macos.plugin.zsh
system/common/zsh.nix
system/common/zsh/outfitting.plugin.zsh
system/common/zsh/hm-profile.inc.zsh
packages/common/programs.nix
packages/common/packages.nix
packages/common/opencode-mcp.nix
packages/macos/programs.nix
packages/macos/packages.nix
packages/macos/zed.nix
packages/macos/Brewfile
fonts/fontget.txt
```

In this mode, `system/macos/flake.nix` must expose `darwinConfigurations`. The manager fetches only these allowlisted paths before activating nix-darwin or applying Homebrew packages.
