The Linux manager stores its state root under `~/.config/outfitting` by default, with machine configuration in `config.toml`. Configure a local checkout or remote Git source there. Linux activates one declared profile at a time; see [Linux configuration](/docs/source-configuration/byor/linux/) for profile selection.

## Apply profile packages (`apply`)

Use [`apply`](/docs/cli/apply/) to install missing packages declared by the selected profile:

```bash
# Reconcile packages with the detected package manager
outfitting-manager apply

# Reuse the previously validated remote snapshot
outfitting-manager apply --no-refresh

# Apply a named profile
outfitting-manager apply --package-manager apt --profile debian-minimal

# Remove packages no longer declared in the active profile
outfitting-manager apply --prune
```

By default, `apply` only adds missing software and never uninstalls anything. With `--prune`, Outfitting only removes packages it previously installed for the active profile and that are no longer declared. Manually installed or pre-existing system packages are protected.

Use `--offline` to reuse only an existing validated source snapshot and skip package-manager network calls. It cannot create a missing snapshot.

## Upgrade installed packages (`update`)

Use [`update`](/docs/cli/update/) to upgrade existing packages:

```bash
# Upgrade packages using the detected native manager
outfitting-manager update

# Select the manager explicitly
outfitting-manager update --package-manager apt
outfitting-manager update --package-manager pacman
```

## Nix and Home Manager

Any Linux profile may declare a Nix flake. Build or activate it separately from native package updates:

To run targeted Home Manager actions:

```bash
outfitting-manager nix build
outfitting-manager nix switch
outfitting-manager nix switch --no-refresh
```

Nix operations read the selected profile's checked-in `flake.lock`. Remote refresh stages and validates the declared source before publishing it. `--no-refresh` reuses the validated snapshot; a local checkout is read directly and never fetched. `--no-push` keeps lockfile changes local. There is no aggregate operation: run `nix switch` and native `update` as separate commands when both are needed.

## Additional tools

- **Manager CLI:** Run [`self-update`](/docs/cli/self-update/) to update the manager binary.
- **Bun packages:** Run `bun update -g` to update global Bun packages.
- **Shell helpers:** See [Home Manager](/docs/cli/linux/home-manager/) for `hm-*` aliases.

For the full command list, see the [Linux CLI reference](/docs/cli/linux/).
