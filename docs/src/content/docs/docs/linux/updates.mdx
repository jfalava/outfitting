The Linux manager stores its state root under `~/.config/outfitting` by default. Machine configuration comes from a local checkout with root `outfitting.json` or a remote source in `byor.json`. Linux activates one declared profile at a time; see [BYOR for Linux](/docs/source-configuration/byor/linux/) for profile selection.

## Apply profile packages (`apply`)

Use [`apply`](/docs/cli/apply/) to install missing packages declared by the selected profile:

```bash
# Reconcile all declared packages
outfitting-manager apply all

# Reuse the previously validated remote snapshot
outfitting-manager apply all --no-refresh

# Apply a named profile
outfitting-manager apply apt --profile debian-minimal

# Remove packages no longer declared in the active profile
outfitting-manager apply all --prune
```

By default, `apply` only adds missing software and never uninstalls anything. With `--prune`, Outfitting only removes packages it previously installed for the active profile and that are no longer declared. Manually installed or pre-existing system packages are protected.

Use `--offline` to reuse only an existing validated source snapshot and skip package-manager network calls. It cannot create a missing snapshot.

## Upgrade installed packages (`update`)

Use [`update`](/docs/cli/update/) to upgrade existing packages:

```bash
# Upgrade native packages and the selected profile's Nix configuration, if declared
outfitting-manager update all

# Upgrade only native packages
outfitting-manager update apt
outfitting-manager update pacman
```

## Nix and Home Manager

Any Linux profile may declare a Nix flake. When present, `update all` switches Home Manager before upgrading native packages. A profile without a Nix declaration only updates native packages.

To run targeted Home Manager actions:

```bash
outfitting-manager update nix build
outfitting-manager update nix switch
outfitting-manager update nix switch --no-refresh
```

Nix operations read the selected profile's checked-in `flake.lock`. Remote refresh stages and validates the declared BYOR source before publishing it. `--no-refresh` reuses the validated snapshot; a local checkout is read directly and never fetched. `--no-push` keeps lockfile changes local.

## Additional tools

- **Manager CLI:** Run `outfitting-manager upgrade` to update the manager binary.
- **Bun packages:** Run `bun update -g` to update global Bun packages.
- **Shell helpers:** See [Home Manager](/docs/cli/linux/home-manager/) for `hm-*` aliases.

For the full command list, see the [Linux CLI reference](/docs/cli/linux/).
