Outfitting manages a Linux development environment with the compiled `outfitting-manager`, native packages (apt or pacman), and optional Home Manager configuration.

## Prerequisites

- Linux x64 or arm64.
- An interactive shell and an account that can use `sudo` when the package manager needs it.
- Network access to GitHub and the Outfitting release assets.

## Install

```bash
curl -L linux.jfa.dev | bash
```

The bootstrap:

1. Picks the matching `outfitting-manager` release (x64 or arm64) and verifies its checksum.
2. Installs the binary on your `PATH`.
3. Runs `init` then `setup` for the default **generic-linux** profile.

It detects **apt** (Debian-family) or **pacman** (Arch-family) from `/etc/os-release` and the installed tools. State lives under `~/.config/outfitting`.

Open a new shell when the installer finishes.

## Profiles (optional)

By default you get the portable package list. Other profiles select a different package manifest and, when present, a Home Manager flake:

| Profile | Role |
| --- | --- |
| `generic-linux` | Default. Native packages only (apt or pacman). |
| `ubuntu-wsl` | Ubuntu package set plus Home Manager under `system/ubuntu-wsl`. |
| `oci-agents` | Headless host package set plus Home Manager under `system/oci-agents`. |

```bash
curl -L linux.jfa.dev | bash -s -- --profile generic-linux
curl -L linux.jfa.dev | bash -s -- --profile ubuntu-wsl
curl -L linux.jfa.dev | bash -s -- --profile oci-agents
```

You can also set the profile later:

```bash
outfitting-manager init --profile ubuntu-wsl
outfitting-manager setup --no-fetch
```

Use a full checkout instead of the sparse source with `--repo /path/to/outfitting` on `init` / `setup`.

For command-level workflows, see the [Linux CLI reference](/docs/cli/linux/), especially [Linux init](/docs/cli/linux/init/) and [Linux install](/docs/cli/linux/install/) for flags.
