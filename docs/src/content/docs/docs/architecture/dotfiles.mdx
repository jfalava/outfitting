Desired state lives in the repo; machine-local operations and locks are pushed to the API worker. Platform install and maintenance pages cover the steps — this page maps the pieces.

## Dotfiles

- `dotfiles/Microsoft.PowerShell_profile.ps1` — Windows shell: `PATH` and the `outfitting-manager` command.
- `dotfiles/.gitconfig` — Windows Git identity and SSH commit/tag signing.
- `dotfiles/ssh.config` — GitHub SSH defaults (`jfalava-gitAuth-elliptic`, legacy `id-ed25519` fallback, `AddKeysToAgent`). Home Manager includes this fragment on Linux and NixOS only. The user-owned `~/.ssh/config` remains editable. macOS does not import this module.

Installers symlink the profile entry points (Windows backs up existing profiles with a timestamp); Apple Silicon, Linux, and NixOS machines link the nix-darwin / Home Manager sources instead.

## System definitions

- `system/macos/` (`darwin.nix`, `home.nix`, `flake.nix`, `zsh/macos.plugin.zsh`) — `outfitting-manager nix` actions, native Homebrew `update`, Brewfile `apply`, `snapshot brew`, and `recover nix`; `hm-build|switch|test|dry` compatibility helpers; remote Nix lock pull/push; and recovery checkpoints under XDG state. Global Bun updates use `bun update -g`.
- `system/ubuntu-wsl/` (`base.nix`, `flake.nix`, `zsh/wsl.plugin.zsh`) — Linux Home Manager profile; `hm-*` via shared `hm-profile.inc.zsh`.
- `system/oci-agents/` (`home.nix`, `flake.nix`, `bootstrap.sh`, `zsh/oci-agents.plugin.zsh`) — headless Linux Home Manager profile and services.
- `system/nixos/` (`configuration.nix`, `desktop.nix`, `server.nix`, `home.nix`, `flake.nix`) — host roles.
- `system/windows/registry/*.reg` — machine tweaks (Recall, Copilot, Ink, developer mode, menu delay).
- `system/common/` (`dotfiles.nix`, `zsh.nix`, `zsh/outfitting.plugin.zsh`, `zsh/hm-profile.inc.zsh`) — shared zsh setup and Linux `hm-*` helpers. `dotfiles.nix` is the Linux/NixOS SSH include. Unix Git identity and signing are rendered by `packages/common/programs.nix`.

## Package manifests

This repository contains desired-state examples under `packages/` and `system/`, but the manager does not infer these profiles or paths. Select a local checkout with `[source] path` or a remote Git repository with `[source] repository` and `ref` in machine-local `config.toml`. Windows profile manifests may use `msstore:<id>` for Microsoft Store entries. Remote source files are selected by the TOML declarations; the unified `windows.lock.json` remains outside the checkout.

## Fonts

`fonts/fontget.txt` lists the 16 public FontGet entries installed by post-install. Licensed fonts ship separately as R2 `releases/fonts.tar.gz` — see [CLI fonts](/docs/cli/fonts).

## Install and reconcile

Root `*-install-script.{sh,ps1}` files are served live from the installer hosts. Linux and macOS bootstraps and the Windows post-install script invoke separate `init`, `apply`, and (where configured) `nix switch` operations. Configure TOML before running them. The Windows font-download portion still accepts legacy raw-route inputs. Registry/OpenSSH setup remains PowerShell; post-install adds Scoop and fonts.

The CLI uses `init` to prepare and validate a source, `apply` to reconcile declared packages, `update` to upgrade native package managers, `nix` for Nix builds and activation, and `self-update` to replace the manager binary. Remote transport is explicit under `outfitting-manager sync`; see [Machine ID](/docs/source-configuration/#machine-id) for how remote state is scoped.
