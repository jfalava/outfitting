## Overview

- [API worker](/docs/architecture/api) — Hono + D1 + KV lockfile storage behind a Bearer gate.
- Router worker — sole public entry; host dispatch, `/api` strip, docs allowlist, `418`/`404`.
- Installer worker — stateless proxy for install scripts and the private font archive.
- CLI — local `outfitting-manager` internals: keychain, provision, upgrade, wire contract.
- [Dotfiles and machine state](/docs/architecture/dotfiles) — what lands on machines and how it is reconciled.

The docs site itself is an optional static asset behind the router (`docs/src/worker.ts` forwards to `DOCS_ASSETS`). When a stack is provisioned with docs skipped, the router has no `DOCS_WORKER` binding and docs paths return `404`.

## Request flows

- State push: `outfitting-manager sync push` → `https://<router>/api/lockfiles/:machine/:kind` → router strips `/api` → API worker verifies the Bearer token, then writes the KV blob and D1 metadata. See [API worker](/docs/architecture/api) and [CLI sync](/docs/cli/sync/).

- Fresh machine: `irm win.jfa.dev/base | iex` (or `curl mac.jfa.dev/post-install | bash`) → installer worker serves the script or protected font archive → platform bootstrap performs machine setup. Current installers still use the retired implicit/raw-route manager source flow and need a separate migration before manager-driven configuration works with BYOR-only source selection. See [Dotfiles](/docs/architecture/dotfiles).

- Font publish: `outfitting-manager fonts publish` packs a new `fonts.tar.gz`, uploads archive then checksum to R2, and rewrites the `outfitting/private-fonts` inventory through the API worker with an `If-Match` precondition. Operator steps and R2 mechanics are in [CLI fonts](/docs/cli/fonts).
