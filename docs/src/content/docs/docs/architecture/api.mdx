Entry is `api/src/index.ts`: every request passes a Bearer gate before routing. The expected token comes from Secrets Store (`OUTFITTING_LOCKFILES_TOKEN.get()`), compared with `timingSafeEqual`. Failures return JSON `ErrorBody`: `401` unauthorized, `404` unknown route, `500` unhandled.

Routes live in `api/src/routes.ts`. Operator usage is in [CLI lockfiles](/docs/cli/lockfiles).

| Method   | Route                               | Result                                             |
| -------- | ----------------------------------- | -------------------------------------------------- |
| `PUT`    | `/lockfiles/:machine/:kind`         | Stores/promotes the body, returns `{ hash, size }` |
| `GET`    | `/lockfiles/:machine/:kind`         | Latest raw content as text, `ETag: "<sha256>"`     |
| `GET`    | `/lockfiles/:machine/:kind/history` | `{ hash, size, created_at }[]`, newest first       |
| `GET`    | `/lockfiles/:machine`               | Sorted JSON array of tracked kinds                 |
| `DELETE` | `/lockfiles/:machine/:kind/:hash`   | Deletes one version, `204` (see guards below)      |

Through the router these paths are prefixed with `/api`; the router strips the prefix before forwarding.

## Conditional writes

`PUT` accepts an optional `If-Match: "sha256"` header (`api/src/lockfiles.ts` `parseIfMatch` requires one quoted lowercase hash). The D1 promotion and head advance are atomic: a stale expected hash returns `412` with the current hash and does not advance the head. `GET` on the latest version sends the hash back as a quoted `ETag` for the next write. Deleting the current head returns `409`; deleting a missing version returns `404`; a malformed hash returns `400`.

## Storage

Content lives in KV as a content-addressed blob keyed `lockfile:{machine}:{kind}:{sha256-of-content}`. Metadata lives in D1 (`api/migrations/`):

- `0001_create_lockfiles.sql` — `lockfiles(machine, kind, hash, size, created_at)`, unique triple.
- `0002_add_lockfile_heads.sql` — `lockfile_heads(machine, kind)` current pointer plus `lockfile_promotions(…, parent_hash)` history/audit.

Writes are append-only and idempotent: re-uploading identical content for the same machine and kind returns its hash without adding history. The KV blob is deliberately retained on version delete because KV and D1 share no transaction — deleting it after the metadata commit could race a concurrent promotion.
